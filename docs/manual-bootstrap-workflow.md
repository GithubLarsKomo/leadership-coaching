# Manual-first bootstrap workflow

Leadership Coaching is LLM-agnostic and, until further notice, uses **manual prompting only**. The application does not call OpenAI, Anthropic, Gemini, Ollama or any other model API.

## Goal

Turn a small provider-neutral bootstrap input into reviewed, versioned assessment artifacts without coupling the runtime to a model vendor.

## Canonical flow

```text
bootstrap-input.json
  -> manual copy/paste with prompts/bootstrap/1.0.0.md
  -> leadership-context.json
  -> schema + semantic review
  -> scorecard.json
  -> initial-round.json / assessment-definition.json
  -> import into Leadership Coaching
```

The runtime begins only after the assessment definition has been reviewed and accepted.

## Evidence maturity

### authoritative
Use when a normative role architecture or competency model is available. The LLM may normalize wording but must not silently replace the supplied model.

### evidence-based
Use when role descriptions, official requirements, policies or other credible sources exist but no complete normative model is available. Derived competencies must be marked `supported` unless direct evidence justifies `confirmed`.

### exploratory
Use when only a role title and coaching objective are known. The resulting model is provisional and must be reviewed before assessment design.

## Step 1 — Prepare bootstrap input

Create a file conforming to `schemas/bootstrap-input-v1.schema.json`.

The input should contain only role-relevant material. Candidate health, family status, religion, politics, ethnicity, sexuality and other irrelevant protected/private information must not be included.

## Step 2 — Normalize leadership context

Copy the system and user-template instructions from `prompts/bootstrap/1.0.0.md` into any capable LLM and substitute:

- `{{bootstrap_input_json}}`
- `{{leadership_context_schema}}`

Save the JSON-only response as `leadership-context.json`.

Record manual provenance in the output:

```json
{
  "creationMode": "manual-llm",
  "promptContract": "leadership-bootstrap/1.0.0",
  "modelReported": "<model name if known>"
}
```

## Step 3 — Validate and review

Validation has two layers:

1. JSON Schema validation;
2. semantic review: no invented authoritative claims, no hidden candidate judgment, competencies are behaviorally observable, unknowns remain explicit.

A schema-valid output is not automatically an approved leadership model.

## Step 4 — Create scorecard and initial assessment

The reviewed leadership context becomes the source for a scorecard and first round. During the manual-first phase these are also generated by copy/paste prompt contracts and imported as JSON. They must preserve references to the leadership-context version.

## Step 5 — Runtime

Once imported, the runtime is deterministic and server-authoritative:

```text
locked round -> unlock -> timed attempt -> answers -> complete -> immutable handoff
```

The subsequent `assess-round` and `generate-next-round` operations are also manual copy/paste workflows until API integration is explicitly introduced.

## API-later rule

Future provider adapters may automate the same prompt contracts, but they must not change domain JSON contracts. Manual and automated generation must remain interchangeable at the artifact boundary.
